# Great White Planet 功能说明

> 本文件由开发者在软件完成后生成（需求文档第九节：帮助菜单 → 功能说明）。
> 软件「帮助 → 功能说明」会优先读取本文件。
> 当前版本：**v2.1.0**

---

## 一、科目（Subject）

首页以**彩色长方体卡片**展示所有科目（需求文档第三节）。

### 科目类型（日记 / 校修课 / 自学课）

新建科目时要**选择类型**，类型决定这个科目的 Book 目录结构与界面标签：

| 类型 | 用途 | Book 目录 | 参与 AI 总结 |
| --- | --- | --- | --- |
| **日记** | 按天记录，AI 归纳思想并合并整理 | `AI summary`、`AI diary`、`my diary`、`else diary` | `my diary` + `else diary` |
| **校修课** | 学校开设、跟着老师上的课 | `book`、`error-prone`、`notebook`、`homework`、`others` | `notebook` + `error-prone` |
| **自学课** | 自己找资料学习的课（默认） | 同校修课 | 同校修课 |

几个要点：

* **自学课的「作业」显示为「练习」** —— 只是界面用词不同，
  目录仍然是 `homework`，功能性质完全不变（不参与 AI 总结）。
  校修课仍然叫「作业」。
* **自学课与校修课都有「其它文件」栏目**（目录名 `others`）：
  放不进取材/笔记/易错题/作业的资料 —— 课件、扫描件、图片、参考文档等。
  **不参与 AI 总结**，并且**可以在里面自由新建文件夹**分门别类
  （右键 →「新建文件夹…」，右键已有文件夹还能继续建子文件夹）。
* **自学课与校修课可以互相改类型**（右键科目卡片 →「修改类型…」）。
  两者的目录结构**完全相同**（`book` / `error-prone` / `notebook` / `homework` /
  `others`），所以切换**不会移动或删除任何文件** —— 只是 `homework` 这个栏目
  在界面上从「练习」变成「作业」（或反过来）。也可以在「编辑名称/类型…」
  对话框里改。
* **日记类型的类型不能改**：它的目录结构（`AI summary` / `AI diary` /
  `my diary` / `else diary`）与普通科目完全不同，硬换要么丢内容、要么留下一堆
  用途不明的目录。菜单里会显示一个**禁用项并写明原因**，而不是让入口消失。
* **日记类型没有教材、没有易错题，也没有「AI 总结」和「简介」** —— 日记不写学习目标，
  输出都在自己的目录里。四个日记专用目录：

  | 目录 | 用途 | 参与 AI |
  | --- | --- | --- |
  | `my diary` | 你自己写的日记（AI 的输入） | ✅ 两套流程都读它 |
  | `else diary` | 别处摘录来的日记、素材 | ✅ |
  | `AI summary` | **AI 思想总结**的产出 | 生成结果 |
  | `AI diary` | **AI 日记**的产出 | 生成结果 |

* **日记页有两套独立的生成功能**（按钮就在顶部）：

  | 按钮 | 做什么 | 产出 |
  | --- | --- | --- |
  | **生成思想总结** | 读 `my diary` 的**全部**日记，归纳思想：反复出现的主题、情绪与心态走势、想法的变化、重复出现的模式，结尾给「值得继续想的问题」。**不复述日记全文**，只在需要时短引用并注明日期。 | `AI summary/<书名>_思想总结.md` |
  | **生成日记** | 把 `my diary` 的**全部内容**按日期合并成**一篇**格式统一的日记册。保留全部事实与语气，只做合并与格式统一。 | `AI diary/<书名>_日记.md` |

  两套流程的提示词都可以在「设置 → 提示词」里改
  （`prompts.diary_thought_system` / `prompts.diary_book_system`）。
  生成前会自动备份上一版，沿用总结的备份机制。

> **AI 助手自称「长庚」**：软件里**所有** AI 助手（学习资料整合、文档问答、
> 日记思想总结、日记整理、日常对话）都自称**长庚**，
> 不会把自己叫成「大白星球」——「大白星球 / Great White Planet」是软件名，
> 而「长庚」是太白金星（金星）的古称，是这个助手的名字。
>
> 想改名字：改 `constants.py` 里的 `AI_ASSISTANT_NAME` 一处即可，
> 7 段提示词共用它。
>
> **提示词版本号**：`prompts.revision` 记录你的提示词是第几版默认值写的。
> 升级软件后如果发现它是旧版，会被自动换成新版并落盘
> （只动提示词，你的其它设置一律保留）。
> 如果你想自己改提示词又不想被自动升级覆盖，
> **把 `prompts.revision` 手动改成当前版本号**即可锁定。

* 「生成日记」输出的每一天格式统一为：

  ```markdown
  ## 2026年5月1日

  天气：

  （这一天的正文）
  ```

  日期按从早到晚排列；原文没有天气就留空，**不会编造**；日期缺失的条目放在最前面，
  标题为 `## 日期不详`。

* **新建日记科目会自动创建一个默认书目**（名叫 `MyBook`），
  打开就能直接写，不需要再手动新建书目。
* **类型可以改，但有条件**：自学课 ⇄ 校修课**可以互相切换**
  （目录结构相同，不动文件）；日记与普通科目之间**不能切换**（结构不同）。
  旧版本创建、没有类型信息的科目一律按「自学课」处理，因此完全向后兼容。

### 文件夹与层级

**栏目里只列"这一层"。** 双击文件夹才进到它里面看内容。

这一条是刻意的（修过一个让人以为"目录乱了"的 bug）：早期版本会把每个子目录里的
文件**也铺出来**，名字做成 `子目录/文件`，于是表格里同时出现

```
第二章
第二章/2.1 极限.md     <- 和文件夹平行，看着像多出来的条目
```

那一行是**假层级**（它根本不在这一层）：右键删它删的是子文件夹里的文件、
拖拽也排不动它。现在文件夹就是文件夹，里面的东西进去才看。

「最近」列表是唯一的例外 —— 它要的正是"所有文件按修改时间排"，
所以那里仍然会列出深层文件（名字带 `子目录/`）。

### 右键菜单

| 在哪儿右键 | 菜单里有什么 |
| --- | --- |
| **条目**（文件/文件夹） | 打开、重命名、删除、复制到…，以及新建/上传/提取 |
| **文件夹** | 上面那些 **+「到它里面新建」**（新建的文件夹会建在它里面） |
| **空白处** | 新建文件夹 / 新建 Markdown / 上传文件 / 粘贴 / 刷新 |

**新建的落点规则**（从最具体到最笼统）：

1. 右键**文件夹** -> 建在**那个文件夹里面**；
2. 正在**浏览某个文件夹** -> 建在**当前这一层**；
3. 右键**普通文件** -> 建在它**旁边**（同一层）；
4. 当前栏目登记的目录（笔记 -> `notebook`，其它文件 -> `others`…）；
5. 虚拟栏目（AI 总结 / 简介 / 全部条目）-> 兜底到 `notebook`。

不能新建时，菜单项会**灰掉并写明原因**，而不是让你点了才弹一句
"请先进入某个书目"。

## 首页日程栏

右侧的「日程」栏把**作业**与**其它日程**合在一起，按 DDL 排序
（未完成在前 -> DDL 早的在前 -> 没 DDL 的最后），每条都能一键「完成」。

### 只显示"还需要你动手"的东西

v2.1 起有两条规则，合起来是一件事：**日程栏只留还没处理完的事**。

| 情形 | 显示吗 | 理由 |
| --- | --- | --- |
| 未完成、期限还没到 | **显示** | 该做的事情 |
| 未完成、**已过 DDL** | **不显示** | 过了截止时间，已经做不了什么了 |
| **已完成** | **不显示**（默认） | 不用再管了 |
| 未完成、**没有 DDL** | **显示** | "没期限"不等于"过期了" |

几个刻意的取舍：

* **「隐藏已完成」默认勾上**（需求），并且**记住你的选择** ——
  你取消勾选后，下次启动还是按你选的来。默认值和"每次启动都掰回去"是两件事。
* **过期的条目会数出来给你看**：面板上显示「另有 N 项已过 DDL，不再显示」，
  鼠标停上去能看到具体是哪几条。**不声不响地让东西消失比藏起来更糟** ——
  用户会以为记录丢了。
* **没有 DDL 的永远显示**。把它们一起藏掉等于"新建的日程凭空消失"，
  那是个严重得多的 bug。
* 已完成的条目若**同时**过期，只按"已完成"处理（不会重复计数）。

## 论坛（自己维护的网址列表）

「论坛」菜单里放的是**你自己维护**的网址列表 —— 想加什么就加什么，
不限于某一个站。

**每一项只有两样东西**：名称 + 网址。

| 操作 | 在哪 |
| --- | --- |
| **打开** | 直接点菜单里的名称（用**系统默认浏览器**打开） |
| **新增** | 菜单 →「新增论坛…」，填名称和网址 |
| **编辑** | 菜单 →「编辑 / 删除」→ 某个论坛 →「编辑…」 |
| **删除** | 菜单 →「编辑 / 删除」→ 某个论坛 →「删除…」（**会先确认**） |
| **调顺序** | 同上 →「上移 / 下移」（菜单顺序 = 你排的顺序） |

几个刻意的设计：

* **网址可以省略 `https://`** —— 填 `cs9.x-way.work` 会自动补成
  `https://cs9.x-way.work`；保存前对话框里会显示"将打开：…"让你确认；
* **用系统浏览器打开**，不用内嵌内核：登录态、Cookie、字体、脚本
  都和你平时上网一致，不用担心兼容性；
* **删除只是从菜单里去掉**，不影响那个网站本身；想加回来重新填一次即可；
* 老版本那一条硬编码的「牢大CS」会**自动变成列表的第一条**，
  你既可以改它，也可以删它。

存的位置：`data\else data\config.json` 的 `forum.list`
（跟着配置走，所以配置备份/迁移会带着它）。

## 作业

### 完成状态怎么显示（颜色规则）

作业列表里，**名称格上的字体颜色**表示完成状态：

| 状态 | 字体颜色 | 文字 | 整行底色 |
| --- | --- | --- | --- |
| **已完成** | 绿色 | 名字（已完成） | **无**（取消颜色标记） |
| **未完成** | 红色 | 名字（未完成） | 无 |
| **未完成** 且临近 DDL（48 小时内） | 红色 | 名字（未完成） | **浅黄** |
| **未完成** 且已过期 | 红色 | 名字（未完成） | **浅红** |

两条规则合起来其实是一条：**底色的作用是催办，只有"还没交"才需要催。**

* DDL 那一格另外标「即将截止」/「已过期」，并用深色字 —— 它说的是
  "期限本身怎么样"，和"你交了没有"是两件事；
* 没设 DDL 的作业不会染色（没有期限就没什么可催的）。

（校修课的「作业」栏目）

校修课的「作业」栏目里，「导入文件」按钮会换成「**创建作业**」——
因为作业不只是文件，还带着 DDL 和提交方式，直接丢文件是表达不了的。

点「创建作业」填四项，**都由你自己决定，软件不做任何猜测**：

| 字段 | 说明 |
| --- | --- |
| **作业名称** | 会成为文件夹名，例如「第三章习题」 |
| **作业内容** | 题目、要求、要交的东西……写成作业文件夹里的 Markdown，随时可再编辑 |
| **DDL** | 日期 + 时间。可以只选日期，也可以**完全留空**（不勾「设置 DDL」） |
| **提交方式** | 一个网址，例如 `https://course.example.edu/upload`。**可留空** |

> **日期时间不用手打数字**：点右边的日历按钮弹出月历**选日期**
> （日历加了字号与网格线，数字看得清；一周从周一开始）；
> 时分则用输入框右侧的**上下按钮**或用**鼠标滚轮**在那个数字上滚 ——
> 年月日时分各自是一段，点一下选中某段再滚，59 分滚回 0 分。
> 好处是**打不出非法日期**，也不用在小格子里对准数字。

落盘结构（每个作业一个子文件夹）：

```
<书目>\homework\第三章习题\
├── homework.json      作业信息：DDL、提交网址、内容
└── 第三章习题.md       作业内容（可直接编辑）
```

> 为什么用子文件夹：一个作业常常要交好几样东西（报告 + 代码 + 截图），
> 子文件夹最直观。而且它就是普通文件夹 —— 在资源管理器里直接看得懂、能整个拷走。

**作业列表**会多出两列，并按截止情况上色：

| 列 | 显示 |
| --- | --- |
| **DDL** | 截止时间；已过期的追加「（已过期）」，**48 小时内**截止的追加「（即将截止）」；没设则写「未设 DDL」 |
| **提交方式** | 一个「**提交作业**」按钮；没填则写「未填写」 |

点「**提交作业**」**不会直接跳走**，而是先弹一个确认框，把**这个作业文件夹的完整路径**
摆在最显眼的位置：

```
作业文件夹   D:\Great White Planet\data\user data\subjects\高等代数\高等代数\homework\2.4 作业
             [复制路径]  [打开文件夹]
提交方式     https://spocnew.buaa.edu.cn/...
DDL          2026-10-11 23:15
文件夹内文件  2 个（不含作业信息文件）
```

* **要交的附件放进这个文件夹** —— 所以先让你看到路径，用「打开文件夹」直接跳过去放；
* 「**提交作业**」才真正打开浏览器（**只打开网页，不上传任何东西**）；
* 「**复制路径**」「**关闭**」是另外两个出口，不想跳转就直接关掉；
* 没填提交网址时「提交作业」按钮是**灰的**，并在悬浮提示里说明原因。

* **不显示网址本身**：教务系统的提交网址常常上百个字符，直接显示会把表格撑得没法看。
  完整网址放在按钮的**悬浮提示**里；需要复制时用右键 →「复制提交网址」。
  这一列是**固定宽度**，多长的网址都撑不开它。
* **一个作业一行**：作业内部的 `homework.json` 与内容 Markdown 不会铺到列表里
  （笔记栏目那种"展开子文件"的行为在这里只会变成噪音）。
* **整行标红** = 已过期；**整行标黄** = 48 小时内截止；没设 DDL 的保持原色。
* 右键作业还能：**编辑作业…**（改内容/DDL/提交方式）、**打开提交网址**、
  **复制提交网址**、在资源管理器中打开、删除。
* **双击作业**仍是打开它所在的位置 —— 交作业请点「提交作业」按钮。

> **双击进到作业里面，能看到这个作业文件夹里的全部文件**：
> 作业内容 md、老师发的图片、你自己放进去的附件，都会列出来。
> 唯一的例外是 `homework.json` —— 它也会显示（不然你会以为文件夹是空的），
> 但**是灰色的、类型写着「作业信息」**：它是软件用来记 DDL 和提交网址的，
> 右键它只有「查看内容（只读）」和「在资源管理器中显示」，
> **没有改名和删除入口**（改掉或删掉会让这条作业丢掉 DDL 与提交网址，
> 而这两件事的关联用户是看不出来的）。
>
> **标签上的数字**数的是"作业个数"，不包含作业内部的文件 ——
> 所以「作业 1」就是 1 个作业，点进去能看到它里面的若干个文件。

> **按钮随"你在哪一层"变化**：
>
> | 位置 | 顶部按钮 | 说明 |
> | --- | --- | --- |
> | 作业栏目**根目录** | 「创建作业」+「导入文件」 | 建新作业，或往作业根目录放东西 |
> | **进入某个作业里面** | 只显示「导入文件」 | 在作业里再建作业不合语境；这里最需要的是**上传附件** |
>
> 所以在 `homework/2.4 作业` 里面点「导入文件」就是往那个作业里加文件
> （也可以直接把文件拖到那一行上）。
>
> **标签上的数字 = 点进去能看到几行**：作业栏目是"一个作业一行"，
> 所以计数**不**包含作业内部的 `homework.json` 与内容文件。
> （曾经用递归数文件，于是标签显示「作业 2」而表格只有 1 行。）
>
> 只有**校修课**的「作业」栏目有这套功能。自学课同一目录叫「练习」，
> 仍然按普通文件夹处理（导入文件），不做作业管理。
> 作业与练习/教材一样**不参与 AI 总结**。

### 科目卡片的其它操作


| 操作 | 入口 |
| --- | --- |
| 新建科目 | 首页右上角「＋ 新建科目」（会先让你选类型） |
| 删除科目 | 右键卡片 →「删除科目…」（**两道确认**，移入回收站） |
| 修改名称 / 类型 | 右键卡片 →「**编辑名称/类型…**」 |
| **只改类型** | 右键卡片 →「**修改类型…（当前：…）**」（有确认框说明不会动文件） |
| 更换图片 | 右键卡片 →「更换卡片图片…」（jpg / png） |
| 移除图片 | 右键卡片 →「移除卡片图片」 |
| 修改颜色 | 右键卡片 →「更换颜色…」 |
| 置顶 | 右键卡片 →「置顶/取消置顶」 |
| 打开文件夹 | 右键卡片 →「在资源管理器中打开」 |
| 调整顺序 | **拖动卡片**到另一个科目上（科目拖到科目上 = 排序；拖到收纳箱上 = 收进去） |
| **新建的排在哪** | **默认排在最后**（不打断你现有的顺序；之后仍可拖拽改） |
| 搜索 | 顶部搜索框按名称/说明过滤 |

* 每个科目 = `data\user data\subjects` 下的一个文件夹，**软件自动扫描生成界面**。
* **首页统计里的「科目」不含日记** —— 日记单独计数：

  ```
  共 2 个科目 · 1 个日记 · 3 本书目 · 1 个收纳箱
  ```

  日记是"按天记录"的东西，和"上什么课"不是一回事，
  混进科目数里会让人以为多了一门课。只有真的存在日记科目时才显示这一段。
* 卡片副标题会显示类型（例如「日记 · 5 个文件」）。
* 卡片图片保存在 `else data/assets/subjects/<科目>`，不污染用户数据目录。
* 直接往 `subjects` 里丢文件夹，然后点首页「刷新」（`F5`）即可识别。

### 收纳箱（把几个科目收在一起）

首页可以把若干科目收进一个**收纳箱**，箱子与普通科目卡片并排显示。

* **新建**：首页右上角「＋ 新建收纳箱」，或右键某个科目 →「移入收纳箱…」→
  「＋ 新建收纳箱并放入…」。
* **放入**：三种方式任选
  1. **直接拖**：把科目卡片拖到收纳箱卡片上（拖到箱子上时边框会变黄提示）；
  2. 右键科目 →「移入收纳箱…」→ 选一个箱子；
  3. 右键科目 →「移入收纳箱…」→「＋ 新建收纳箱并放入…」。
* **打开**：**单击**收纳箱卡片即展开（不需要双击）；展开后主界面
  **只显示箱内的科目**，右上角出现「**✕ 关闭收纳箱**」按钮 —— 它是**唯一的退出入口**，
  点它回到「我的科目」总览。也可以双击展开，或用菜单「查看 → 首页」回来。
* **移出**：**右键那个科目** →「**移出收纳箱：<箱名> → 最外层**」。

  * 这一项**只要科目在箱子里就会出现**（不管你现在是在箱内看，还是在总览里看），
    因此永远找得到"怎么拿出来"；
  * 科目不在任何箱子里时，同一位置显示的是「移入收纳箱 …」（两者互斥，不会混淆）；
  * 箱内右键还有「移动到其它收纳箱 …」，可以直接换到别的箱子，不必先移出；
  * 也可以**单击选中科目后按 `Shift+Delete`** 移出；右键箱子 →
    「把箱内科目全部移出」则一次清空；
  * 按 `Esc` 关闭收纳箱回到总览。
* **调整顺序**：**拖动卡片**即可改变显示顺序。最外层是**一张混排列表** ——
  收纳箱和科目可以交替排列。

  | 拖动 | 结果 |
  | --- | --- |
  | **收纳箱 → 科目** | **混排**：插到那个科目前面（左半边）/ 后面（右半边） |
  | **科目 → 收纳箱卡片** | **收进箱子**（不是排序） |
  | 科目 → 另一个科目（都在最外层） | 插到那个科目前面 / 后面 |
  | 科目 → **同一个箱子里的**科目 | **调整箱内顺序** |
  | 科目 → **别的箱子**里的科目 | 搬进那个箱子，并插到目标位置 |
  | 科目 → 未收纳的科目 | 移出箱子，并排到那个科目旁边 |
  | 收纳箱 → 另一个收纳箱 | 调整收纳箱之间的顺序 |

  落点在卡片**左半边**插到前面、**右半边**插到后面，拖动时目标卡片边缘会显示
  一条黄色竖条指示位置。

  三种顺序都写进元数据（科目的 `subject.json`、收纳箱的 `boxes.json`），
  **重启后仍然保持**。箱内顺序是**每个箱子独立**的。

  > 注意「科目拖到收纳箱」和「收纳箱拖到科目」是两件不同的事：
  > 前者是**归类**，后者是**排序**。想调整箱子与科目的相对位置，拖**箱子**。

* **箱子的右键菜单**：打开、重命名、更换边框颜色、更换/移除卡片图片、
  清空、删除。

**样式**：收纳箱卡片与科目卡片**完全一致**（同样的尺寸、圆角、渐变、徽标、
标题与副标题排版），唯一区别是收纳箱多了**一圈常驻边框**（颜色取箱子主色，
拖拽悬停时变黄），徽标显示的是箱内的**科目数**。

**安全性**（重要）：

* 收纳箱**只记录分组，不搬动任何文件** —— 科目仍然是
  `user data/subjects/<科目>` 下的普通文件夹；
* **删除收纳箱不会删除任何科目或文件**，箱内科目只是回到最外层；
* 一个科目最多属于一个箱子，放进新箱子会自动从旧箱子移出；
* 你手工删掉/改名科目文件夹后，箱子里的失效记录会被自动清理，不会报错。

分组信息存在数据根目录的 **`boxes.json`**（与 `user data` / `else data` 平级），
可以直接用文本编辑器改；备份 `user data` 时连同它一起复制即可保留分组。

## 二、首页右侧：日期 / 天气 + 日程栏

首页右侧上方是**日期 · 时间 · 天气**信息条，下面是**日程栏**。

### 日期 / 时间 / 天气条

```
2026年10月9日 星期五                    16:39:36
中国 · 北京市                            25°C 阴
```

| 位置 | 内容 |
| --- | --- |
| 左上 | 日期 + 星期（`2026年10月9日 星期五`） |
| 右上 | 时间，带秒，**每秒刷新** |
| 左下 | **地区**（按网络定位自动得到，转成中文地名） |
| 右下 | 温度 + 天气情况（`25°C 阴`） |

**体感温度 / 湿度 / 风**只在**鼠标悬停**时显示（需求：最后一项悬浮显示）：

```
中国 · 北京市
温度 25°C
体感 23°C
湿度 36%
风 11 km/h（南风）
观测 2026-10-09 16:45
```

**天气数据从哪来**（不需要配置、不需要 Key）：

1. **定位**：按出口 IP 大致定位，三个免费接口依次尝试
   （`ipapi.co` → `ip-api.com` → `ipwho.is`；实测第一个常返回 403，所以必须有备选）；
2. **中文地名**：用城市名去 Open-Meteo 的地理编码接口换中文名
   （注意：Open-Meteo **没有**反向地理编码接口，`/v1/reverse` 实测 404）；
3. **天气**：`Open-Meteo` 免费预报接口，取温度、体感、湿度、风速风向、天气代码。

**天气只在启动时拉一次**（需求如此）。抓取放在**后台线程**里 ——
这些接口在慢网络下要几秒到二十秒，放主线程会把界面卡住，而它只是锦上添花的信息。

* 抓取中显示「天气获取中…」，成功填上温度与地区；
* **失败显示「天气获取失败」或「无法定位（可能没联网）」**，灰色小字，
  **不弹窗、不阻塞**（断网是常态）；
* 有**总时间预算 12 秒**，超时就用失败态收尾，不会一直转圈；
* 请求用**短超时分片轮询**，每片之间检查一次取消标志 —— 所以关闭软件时
  正在进行的请求会立刻中止，关窗不会被网络请求拖住。

**可以关掉**（设置 → 界面，改完立即生效，不用重启）：

| 开关 | 关掉后 |
| --- | --- |
| **首页显示日期与时间** | 整条信息条不显示（日程栏上移） |
| **显示天气（会联网获取）** | 只显示日期与时间，天气位置写「天气已关闭」，**完全不联网** |

### 日程栏

首页右侧是一栏**日程**，把两样东西合成一条按时间排开的清单：

| 来源 | 从哪来 | 说明 |
| --- | --- | --- |
| **作业** | 自动扫描所有科目 / 书目下的 `homework/<作业名>/homework.json` | 不用手动登记；在校修课里创建作业就会出现在这里 |
| **其它日程** | 数据根目录的 `schedule.json` | 与科目无关的待办：考试、报名截止、要办的手续…… |

### 排序规则

**未完成在前 → DDL 早的在前 → 没设 DDL 的排最后 → 名称**。

没设时间的排在后面（而不是当成"很早"），否则一堆没时间的日程会顶到最前面，
把真正临近截止的挤下去。

### 每条日程上有什么

| 元素 | 说明 |
| --- | --- |
| 勾选框 | 与下面的按钮是同一个动作，两种习惯都能用 |
| 名称 | 逾期红字；已完成的**划线变灰** |
| 时间 | 已过期的追加「（已过期）」并标红；48 小时内截止的标黄并追加「（即将截止）」 |
| 来源 | 作业显示 `科目 / 书目`；其它日程显示「其它日程」 |
| **完成** | **完成按键**（需求要求）。作业会同时把 `done` 写进它的 `homework.json` |
| 打开 / 提交 | 作业专用：打开它所在的文件夹 / 走提交确认框 |
| 编辑 / 删除 | 其它日程专用 |

* 左边有一条**彩色竖线**：红=已过期、黄=即将截止、绿=已完成、灰=还早。

#### 宽度：只有「完全展开」和「全部折叠」两态

日程栏的宽度是**固定的**，不能拖：

| 状态 | 宽度 | 怎么切 |
| --- | --- | --- |
| **完全展开**（默认） | 380px | 点面板右上角的 **»** |
| **全部折叠** | 48px（一条窄边） | 点窄边上的 **‹** |

* 分隔条**不能拖动**（handle 宽度 0、交互已禁用），所以宽度永远只有这两个值；
* 折叠后是一条**贴住窗口右缘的竖向页签**：顶部 **‹** 展开箭头、
  中间竖排的「**日程**」字样、底部一个圆角徽标显示**未完成条数**；
* **日期/时间/天气条也归日程栏管** —— 折叠时和它一起收起。
  这样折叠后整列就只有 48px，竖条才真的贴在右缘
  （曾经它是独立一行、最小宽 329px，把整列撑住，于是竖条贴左、右边空出一大片）；
* 点 **»** 收起、点 **‹** 展开 —— 两个方向都有入口，不用猜。

> 为什么不给连续可拖：日程栏内容只有三行文字 + 三个按钮，
> 宽度在 336～480 之间拖来拖去**没有实际收益**，反而经常被不小心拖窄、
> 把「提交」按钮挤掉。固定两态既够用又不会拖坏。

#### 窗口变窄时科目卡片会自动换行（不会躲在日程栏后面）

科目卡片的列数是**跟着可用宽度算的**：

| 科目区可用宽度 | 列数 |
| --- | --- |
| 不够一列 | 1 |
| 约 520px | 2 |
| 约 720px | 3 |
| 约 1020px | 4 |

而且当窗口窄到**放不下「一列卡片 + 展开的日程栏」**时，
日程栏会**自动折叠**把位置让给卡片（状态栏会提示"空间不够，日程栏已自动折叠"）。
想展开点一下 **‹** 就行；**变宽后它不会自己弹回来**（免得来回跳）。

> 之前的行为是：网格的最小宽度被钉在"所有卡片排成一行"，
> 窗口变窄时它不肯收缩，右边的列被滚动区裁掉 ——
> 看起来就像"日程栏把科目卡片遮住了"。

#### 「打开」按钮：在软件内跳转（不是开资源管理器）

点日程行上的「**打开**」，会**在软件内部**跳到这本书目的**作业栏目**，
并直接进入那条作业的文件夹 —— 和双击文件夹看到的东西一模一样。

> 需求原话："日程栏打开按键点击后在软件内打开对应Book的homework栏目，
> 不是打开本地文件夹"。
>
> 想看资源管理器的话：在作业栏目里右键 →「**在资源管理器中显示**」。
> 两条路都留着，但默认那条不再打断你。
* 顶部有「**＋ 新建日程**」和「**隐藏已完成**」两个入口。
* **每个任务显示四行**：标题 / 来源 / **DDL（单独一行、加粗）** / 备注（有才显示）。
  DDL 单列一行是为了避免"来源名字太长把 DDL 挤到下一行"看起来像排版坏了。
* **行高会自动适应内容**：内容多（长标题换行、有备注）时该行自动变高，
  不会裁掉文字。另有最小高度配置 `ui.schedule_row_height`（默认 88px，下限 44px）。
* 计数写着「待办 N / 共 M」，一眼知道还剩几件。

### 其它日程存在哪

```
data/
├── boxes.json        收纳箱
├── schedule.json     其它日程      <- 与 boxes.json 同级
└── user data/
    └── subjects/...
```

为什么不塞进某个书目里：日程是**跨科目**的视图，硬挂在某门课下反而别扭；
而且首页要同时列出不同科目的作业，散落在各书目里就得扫描整棵树才能凑齐。

存储用"读-改-原子写"，所以**可以手工编辑** `schedule.json`，软件改动它也不会互相破坏。

## 三、书目（Book）
点击科目卡片进入书目列表（需求文档第四节）。

> **新建的书目默认排在列表最后**（不打断你现有的顺序），之后仍可拖动调整。

每个书目创建时**自动生成**以下结构：

```
<书目名称>
├── Introduct.md            用户自行编辑，记录简介与学习目标
├── <书目名称>_summary.md   AI 生成的结构化总结文档
├── book                    电子教材、PDF 教材
├── error-prone             易错题、易错内容
├── notebook                用户笔记
├── homework                作业
├── others                  其它文件（不参与 AI 总结，可自建子文件夹）
└── book.json               书目元数据（名称/颜色/排序等）
```

| 目录 | 用途 | 参与 AI 总结 |
| --- | --- | --- |
| `Introduct.md` | 简介、学习目标、备注 | ✅ |
| `notebook` | 用户笔记（含 PDF、图片） | ✅ |
| `error-prone` | 易错题、易错内容 | ✅ |
| `homework` | 作业（校修课）/ 练习（自学课） | ❌ **不参与** |
| `book` | 电子教材、PDF 教材 | ❌ **不参与**（代码级排除，改配置也不会参与） |
| `others` | 其它文件：课件、扫描件、参考资料等 | ❌ **不参与** |
| `<书名>_summary.md` | AI 整合结果 | 生成产物 |

> **标题区只显示书名**；每个栏目有多少条内容，直接标在**标签上**
> （例如「笔记 3」「易错题 1」「全部条目 6」）。数量为 0 的栏目不带数字，
> 避免一排 `0` 造成视觉噪声。
>
> **数字的含义统一为"点进去能看到几行"**：
> 笔记/易错题/教材/其它文件是"数文件"（子目录里的文件也会铺出来，所以数文件才准）；
> **作业栏目是"数作业"**（一个作业一行，内部 `homework.json` 不算）。
> 这样标签上的数字永远和表格行数对得上。

> **`others` 是什么**：一个"什么都能放"的栏目。因为取材/笔记/易错题/作业都有明确
> 含义，剩下的东西（老师发的课件、拍的照片、别人的笔记）放哪都不合适。
> 它**完全不参与 AI 总结**，所以往里放多少东西都不会影响总结质量；
> 而且**可以自由建子文件夹**（右键 →「新建文件夹…」），适合按章节/来源分门别类。
>
> 它和 `book` / `homework` 一样被当作**固定结构目录**保护：不能剪切或复制走。

> 旧版本创建的书目在**首次打开时**会自动补上缺失的 `others`、`homework` 目录
> （幂等操作，不会在启动扫描时改动你的数据）。

书目的右键菜单：打开、重命名、编辑说明/颜色、置顶、**补齐标准目录结构**、
在资源管理器中打开、**移动到其它科目**、删除（进回收站）。

### 新建文件夹 / 新建 Markdown

在书目页**右键**任意条目，菜单最上面有：

| 动作 | 建在哪 |
| --- | --- |
| **新建文件夹…** | 右键点在某个文件夹上 → 建在**那个文件夹里**；否则建在**当前分类目录**里 |
| **新建 Markdown…** | 同上 |

因此在「其它文件」里可以任意分层：`others\第一章\课件\`、`others\模拟卷\` 都行。
重名、空名、含 `\ / : * ? " < > |` 的名称都会被拦下并给出提示。

## 四、书目页：资料管理

界面分左右两栏：

* **左侧分类标签**（**AI 总结排第一**，对应需求文档「summary 默认位于 Book 首位」）：
  AI 总结 / 简介 / 笔记 / **作业** / 易错题 / 教材 / 全部条目。
  进入书目时默认停在「AI 总结」页。
* **右侧详情面板「资料概览」**：资料统计、总结状态与版本、快速操作、最近修改列表。
  该面板**默认折起**（不占用资料列表宽度）；点页面上方操作区的
  **「资料概览」按钮**展开，展开后点面板标题栏的 **▾**（或双击标题文字）收起。
  折起状态与展开宽度都会被记住。

### 导入资料

* 「导入文件…」按钮，或**直接把文件拖进窗口**（自动放进当前分类）。
* 支持：`md` `markdown` `txt` `pdf` `docx` `pptx` `xlsx` `csv`
  `png` `jpg` `jpeg` `webp` `bmp` `gif` `tif`。
* 默认**复制**而不是移动；同名文件可选择覆盖或自动改名（`_1`、`_2`…，后缀可在设置里改）。
* 在「AI 总结 / 简介 / 全部条目」标签下导入时，会让你先选放进哪个分类。

#### 拖拽上传的落点规则（重要）

**拖到哪一层，就传进哪一层**。具体三条：

| 你拖到的位置 | 文件会进哪 |
| --- | --- |
| 表格的**空白处** / 窗口其他位置 | **当前正在看的目录**（进入了子文件夹就是那个子文件夹） |
| 某个**文件夹那一行**上 | **那个文件夹里面**（少一步手工移动） |
| 「作业」栏目的空白处 | `homework/`（作业根目录） |

* 拖动时标签条那一行会显示「**拖到这里 → others / 第一章**」，
  松手前就能看到确切落点；
* 导入完成后状态栏写的是**相对书目的完整路径**（如「已导入 2 个文件到 others / 第一章」），
  不再只给一个文件夹名 —— 一眼能核对有没有放错层级；
* 不想拖也可以：**右键文件夹 →「上传文件到「xxx」…」**，
  或右键空白处 →「上传文件到当前目录…」。

> 历史 bug：早期版本只按"栏目登记的目录"落点、**不看你浏览到哪一层**，
> 所以进了 `others/第一章` 再拖文件会被丢到 `others`（上一级）。
> 现在落点以"你正在看的目录"为准。

### 图片提取为 Markdown

把**一个文件夹里的多张图片**（拍的课件、扫描的讲义、板书照片）用 AI 逐张转写成
文字，合并成一份 Markdown。**入口**：

* 工具菜单 →「**图片提取为 Markdown…**」（作用于当前所在目录）；
* 右键文件夹 →「**提取「xxx」里的图片…**」。

#### 核心设计：**没把握就直接插图片，绝不编内容**

这是这个功能的安全底线。AI 看图一定会遇到看不清的情况，
而**编造出来的复习资料比缺失的内容危险得多**。所以：

| 情况 | 处理方式 |
| --- | --- |
| 识别正常 | 用 AI 的正文 |
| 内容太短（几乎没读出东西） | **插入原图** |
| AI 自己说「无法辨认 / 看不清 / 抱歉」 | **插入原图** |
| 正文里出现 `[[无法辨认]]` 占位符 | **插入原图** |
| 乱码字符过多 | **插入原图** |
| **你自己标记「没把握」** | **插入原图** |

插入时会带一段醒目提示，写明**为什么**没采信：

```markdown
## 2. 第2页.png

> ⚠️ **这一页没能可靠识别**，因此直接插入原图，请自行查看。
> 原因：AI 自己表示看不清：无法辨认、抱歉

![第2页.png](第2页.png)
```

图片用**相对路径**引用，所以整个文件夹搬到别处链接也不失效。

#### 你能随时插手

AI 的判断不是最终裁决 —— **你看过原图，你说了算**：

| 按钮 | 作用 |
| --- | --- |
| **提取选中的 / 全部提取** | 逐张处理（待处理的才处理） |
| **标记为没把握** | 选中的改为「插入原图」，不多写一个字 |
| **改为用文字** | 取消"没把握"，恢复正文（没正文的会提示先去提取或手写） |
| **编辑正文…** | 手动改文字；**改过之后就不再被自动判为不可信** |
| **只看提示词** | 不调用 AI，只显示该发给它的提示词 |

#### 两种识别方式，自动选

| 你的配置 | 走哪条路 |
| --- | --- |
| 「设置 → AI」里勾了「**允许把图片发送给 AI**」，且有声明支持视觉的模型 | **全自动**：直接发给模型，你不用粘贴 |
| 否则（默认） | **网页版桥接**：图片和提示词自动进剪贴板 → 打开网页 → 粘图片、粘提示词 → 把回答粘回弹窗 |

> **默认不发图片**是有意的：图片可能是作业照片、证件、手写笔记，
> 发出去有隐私含义，必须你明确同意。
> 网页版桥接则完全不经过软件的 AI 配置 —— 图片只进你自己的剪贴板，
> 由你决定粘给谁，零密钥、零费用。

> **文件名与位置**：结果落在**当前文件夹**里，名字形如
> `第一章_图片提取_2026-10-10.md`（带日期，同名自动改名，不覆盖）。
> 想让它参与 AI 总结，就把它移动到「笔记」栏目。

> **顺序**：按**自然顺序**处理，`第2页` 在 `第10页` 之前
> （朴素排序会把 `第10页` 排到前面，对按页拍的照片来说顺序全乱）。
> 勾选「包含子文件夹里的图片」可以一次处理"一章一个子文件夹"的相册式整理。

### AI 对话栏

* 输入框上方是**附件区**（没附件时不占地方）；
* 输入框下方：**发送** / **停止** / **附件** / **重发文件** / **插入文档** / **清空**；
* `Ctrl+Enter` 发送；
* AI 不确定时会弹窗提问，回答后自动继续；
* 关闭时保存聊天记录（可在设置里改）。

#### 附件（发给 AI 的文件）

点「**附件**」选文件。**注意：这不是把文件"上传"到某个服务器** ——
当前 AI 是文本模型，API 收不了文件。所以按类型走两条路，**都在本地完成**：

| 你选的类型 | 会发生什么 |
| --- | --- |
| **PDF / Word / PPT / Excel / CSV / 文本 / 代码** | **本地把正文提取出来**（转成 Markdown），随提问一起发给 AI |
| **图片** | 需要视觉模型；否则**明确告诉你"内容没传进去"**，并给出替代做法 |

> **为什么文档要"本地提取"而不是让 AI 看**：PDF 有文字层、docx 有结构化段落，
> 本地提取是**确定性的**（同一份文件每次都得到同样结果），
> 比让 AI "看图猜字"可靠得多，而且离线、免费、你可以自己核对提取结果。

**如实告知，绝不假装读过**：

* 每份附件旁边都写明状态（`已提取 1234 字` / `图片（需要视觉模型）` /
  `旧版 Office 格式无法直接解析`）；
* 提取失败的附件**照样列出来并说明原因**，不会让 AI 对着一个文件名编内容；
* 首次发送时会**明确警告**：图片的内容没有包含在对话里。

**其它行为**：

* 单份附件默认最多送 **20000 字**，一次对话合计 **60000 字**
  （超出会截断并在状态里写明"原文 N 字，超出部分未发送"）；
* 超长内容**不会悄悄丢掉**，一定告诉你；
* **发送后输入区的附件自动清空** —— 内容已进聊天记录（后续追问仍能看到），
  但不会在每一轮里重发全文（否则会挤满上下文、让回答变差）；
* 重复选同一个文件会被跳过；
* 只想发附件、不打字也可以，会自动补一句"请阅读我上传的附件，并总结要点"；
* 附件名会记进聊天记录，便于回溯。

> **想让图片也能直接发**：在「设置 → AI」里勾选「**允许把图片发送给 AI**」，
> 并配一个支持视觉的模型（通义千问 qwen-vl、智谱 glm-4v、OpenAI gpt-4o 等）。
> 默认不勾是**有意**的：图片可能是作业照片、证件、手写笔记。

### 关闭到后台（软件常驻）

> 需求："考虑到软件启动慢，当主界面关闭，软件在后台运行，
> 除非用户手动用任务管理器将其任务终止。"

**默认开启**：点主窗口的关闭按钮**不退出进程**，只是把窗口藏起来。
下次要用的时候是**瞬间**出现的，不用再等一次启动。

| 操作 | 效果 |
| --- | --- |
| 点窗口的 **✕** | 窗口隐藏，**进程继续在后台运行** |
| **双击右下角托盘里的星球图标** | 窗口回来 |
| **再双击一次桌面快捷方式** | 窗口回来（**实测 0.3 秒**） |
| 托盘图标 **右键 →「完全退出」** | 真正退出进程 |
| 菜单「文件 → 退出」 | 真正退出进程 |
| 菜单「文件 → 隐藏到后台」 | 等价于点 ✕ |

* 第一次隐藏时会弹一个气泡，说清"怎么找回来、怎么彻底退出"（**只弹一次**）；
* 关掉「设置 → 常规 → 关闭主窗口时最小化到后台」后，点 ✕ 就真正退出；
* **有未保存的文档时仍会先问你** —— 不会因为"反正不退出"就跳过保存确认；
* 真正的退出会照常执行清理（保存聊天记录、按配置清空、停掉天气线程、释放实例锁）。

> **托盘不可用时**（极少见）不会静默退出，而是退化成"最小化到任务栏"，
> 并且仍然可以通过双击快捷方式唤回 —— 避免出现
> "关了窗口、没有托盘、只能开任务管理器"这种最坏情况。

#### 唤回是怎么实现的（为什么不能"替它打开"）

第二个进程**不能替第一个进程把窗口显示出来** —— 那样会得到一个全黑窗口：
原生窗口确实变可见了，但 Qt 不知道，于是不重新布局、也不重绘。

所以实际做法是"**请求**"：第二个进程在 `else data\wake.request` 留一个标记，
第一个进程用 600ms 的定时器看到它就**自己**调 `show()` ——
显示与重绘都走 Qt 自己的流程。实测**约 0.6–0.8 秒**唤回，画面完整。

> 另一个"看起来更专业"的方案（发自定义 Windows 消息 + 在窗口的
> `nativeEvent` 里接住）在 **PyQt6 6.11 上会直接崩溃** ——
> 连"什么都不做、只转发给父类"都崩（退出码 `0xC000041D`）。
> 所以选了"文件 + 轮询"这个笨但可靠的做法。

> **为什么值得常驻**：启动一次要重建整个界面并预热扫描；
> 留在后台后，"再次打开"就只是把窗口显示出来 —— 这是**感知上的免费**。

### 单词书（单词卡）

**每个书目**都有一个「**单词书**」栏目，用来记生词。它和别的栏目不一样：
**不是文件列表，而是一列可折叠的单词卡**。

#### 用法：只填英文，其余交给 AI

1. 点「**添加单词**」，只输入**英文单词或短语**（`abandon`、`give up`、`a.m.`）；
2. 弹出的确认框里选「是」，AI 会自动补齐：
   **音标、词性、中文释义、例句（带翻译）、常用搭配、记忆提示**；
3. 卡片**默认折叠**，只显示英文；**单击卡片**就展开看释义。

#### AI 是**软件直接调用的**，不需要你自己去问（v2.1 修正）

**你只要填英文，剩下的是软件去办。** 它直接调用你在设置里配好的 AI。

这条在 v2.1 修过，原来不是这样：`web_bridge.send_to_ai` 里**只有带图片的
请求**才会直连 API，纯文本一律走"复制提示词 + 打开网页 + 让你粘贴回答"
那条兜底路。单词卡是纯文字，于是**即使用户已经配好了 API Key，
也还是被要求手动粘贴** —— 那显然不对。

| 你的 AI 配置 | 补齐时走哪条路 |
| --- | --- |
| **配好了 API Key**（DeepSeek / GPT / 本地命令 / 自定义 API） | **直接调用 API**，全自动，零粘贴 |
| 只配了**网页版**（DeepSeek 网页 / GPT 网页） | 复制提示词 + 打开网页 + 你粘贴回答 |
| **一个都没配** | 同上（手工那条路仍然留着，不会被堵死） |

> **带图片的任务另有一条更严的判据**（例如"把图片里的文字提取出来"）：
> 必须提供方**声明支持视觉**、并且用户**显式允许发送图片**才会直连 ——
> 发图有隐私含义，不能悄悄发。纯文本没有这个问题。

**模型不按格式回答也不会写进乱码**：提示词要求 `examples` / `phrases` 是
"每行一句"的**字符串**，但模型经常返回**数组**。v2.1 之前这里会把数组
直接 `str()` 一下存进卡片，卡片里就出现
`[{'en': 'Smartphones...'}]` 这种人形乱码；现在两种形状都接受，
数组会按 `英文 —— 中文` 拼成正常的行文本。

#### 补齐在**后台线程**里跑，不会卡界面（v2.1 修）

这条也是 v2.1 修的，起因是用户报障："**单词补齐功能障碍，会导致程序卡死**"。

根因很直接：补齐时**在界面线程里同步调用 AI**。

* 单张：网络一慢，点完那一下界面就没反应了；
* **「补齐全部」**：在界面线程里 `for` 循环**逐张**请求，N 张卡 = N 次串行
  网络往返，界面被冻住的时间是这些请求加起来的总和。

现在照「AI 学习总结」的做法走后台线程：

| 谁 | 干什么 |
| --- | --- |
| **后台线程**（`AIWorker`） | 只负责**取 AI 的回答**，一张一张问 |
| **界面线程** | 负责解析、合并、读写卡片文件（磁盘 IO 很快，不会卡） |

* 进度显示在进度框里（`正在补齐 3/10：abandon`），**随时可以取消**；
* 补齐期间界面照常能用：可以切标签、滚卡片列表；
* 「补齐全部」结束后汇总"成功 N 张、跳过 M 张"，并列出跳过的词。

> **「补齐全部」需要能直接调用的 AI**（在「AI → AI 设置」里填了 API Key）。
> 只配了网页版时会提示你先配 API —— 因为批量补齐如果走"复制提示词 + 粘贴"，
> 会为每张卡各开一个浏览器窗口、各弹一次粘贴框，那显然不成立。
> 这种时候请逐张右键「AI 补齐」。
>
> 反过来，**后台线程里绝不会**执行"复制提示词 / 开浏览器 / 弹粘贴框"：
> Qt 不允许在非 GUI 线程里创建控件，那样会直接把进程弄崩。

#### 折叠 / 展开（这是明确的交互契约）

| 状态 | 显示什么 |
| --- | --- |
| **折叠**（默认） | **只有英文** + 一个 ▸ 箭头（还没补齐的会多一个「待补齐」标记） |
| **展开** | 音标、词性、中文释义、例句、搭配、记忆提示、你自己的笔记 |

* **单击卡片的任意位置**就切换（不用专门去点那个小箭头）；
* 展开状态**会被记住**，刷新后不丢；
* 「**全部展开 / 全部折叠**」一次搞定所有卡片。

#### 其它

| 操作 | 说明 |
| --- | --- |
| **补齐全部** | 把还没有释义的卡片逐张交给 AI |
| **搜索** | 英文和中文都能搜（搜「放弃」能找到 `give up`） |
| **右键卡片** | AI 补齐 / 重新补齐（覆盖）/ 编辑… / 复制单词 / 复制释义 / 锁定 / 删除 |
| **编辑…** | 按「字段名: 值」逐行改（`meaning: 释义`、`examples: 例句`…） |
| **锁定** | 锁上之后 AI 不会自动覆盖它 |

> **AI 补齐失败时不会瞎写**：AI 说"查不到该词"或回答不是可解析的格式时，
> 这张卡**保持原样**并提示你手动编辑 —— 不会往卡里塞编造的内容。
>
> **你自己改过的内容不会被冲掉**：重新补齐默认**只填空白字段**；
> 想整张重写要显式选「重新补齐（覆盖现有内容）」。

**卡片存在哪**：**所有科目、所有书目共用一个单词书** ——

```
<数据目录>/user data/wordbook/<英文>.json
```

**不在任何科目或书目下面**。所以你在「英语1 视听说」里记的 `abandon`，
打开「英语2 阅读」「高等代数」的单词书栏目也都能看到 ——
生词本是跨教材累积的东西，按书目切开就失去意义了。

**一张卡一个文件**：方便单独手工改、单独拷给同学，也能直接进版本管理（Git）。
json 合法但内容不像卡片时会被跳过（校验内容，不靠文件名猜）。

> **从旧版本升级**：早期版本是"每本书一个 `wordbook/`"。
> 启动时会**自动把这些卡片迁移**到共用目录 ——
> 重名的卡会**改名保留**（`give up (来自英语-英语1).json`）而不是覆盖，
> 两张都有价值；迁移后清掉空的旧目录，不留两份让人困惑。
> 迁移是幂等的，跑多少次结果都一样。

#### 打开方式（按类型分流）

| 文件类型 | 用什么打开 |
| --- | --- |
| **JSON / 源码 / 配置** | **VSCode**（找不到就退回内置只读查看器） |
| Markdown / 文本 | 软件内部的 Markdown 编辑器 |
| 图片 / PDF | 软件内部查看 |
| Word / Excel / PPT | 系统默认程序 |

> JSON 之所以优先用 VSCode：它是配置/结构化数据，**你多半想改而不是只看**，
> 而 VSCode 有语法高亮、折叠、校验。找不到 VSCode 时会退回内置的只读查看器，
> 保证"至少能看"。

#### 在文件夹里操作时不会跳出去

双击文件夹就进入它；**在里面做任何操作（删除、重命名、导入、拖拽上传、新建文件夹）
之后，你仍然停在这个文件夹里**，不会被打回上一层。
标题栏会写明当前位置，点「↑ 上一层」才退回。

#### 任务栏图标（为什么要设"应用标识"）

任务栏按钮的图标**不是**由窗口自己画的那个决定的 —— Windows 会先按
**应用标识（AppUserModelID）** 把窗口归到一个"应用"下，再用那个应用的图标。

从源码运行时进程是 `venv\Scripts\pythonw.exe`。不设标识的话，
Windows 就把窗口归到 **Python** 名下，任务栏显示的是**解释器图标**
（一个蛇形图标），而不是我们的星球。

所以启动时会：

1. 在建窗口**之前**把当前进程的标识设成 `GreatWhitePlanet.LocalKnowledge`；
2. 让桌面快捷方式写**同一个**标识 —— 这样"双击快捷方式启动"
   与"已在运行的实例"被认成同一个应用，任务栏不会出现两个图标；
3. 如果桌面上那个快捷方式是**旧版本**创建的（没有标识），启动时顺手补上。

> 这就是"任务栏图标改成快捷方式现在的图标"的做法：
> 两者用同一个身份，任务栏就取用 `planet.ico`。

#### 改作业名

改作业名有**两个入口**，两个都会把「文件夹名 + 作业信息 + 内容文件名」一起改掉：

| 入口 | 位置 |
| --- | --- |
| 「编辑作业…」 | 右键作业 → 编辑作业…，在「作业名称」栏改 |
| 「重命名作业…」 | 右键作业 → 重命名作业…（菜单上会写明它同时改作业信息） |

改名的效果：

* **作业文件夹会一起改名**，里面的文件（含作业内容 Markdown、附件）都跟着走；
* `homework.json` 里的名字同步更新，DDL 与提交方式**不会丢**；
* 新名字和别人重名时会**拦住并提示**，不会覆盖已有作业；
* 如果你自己改过内容 Markdown 的文件名，改名时**不会动它**
  （只有在它仍与旧文件夹同名时才跟着改）。

> 早先版本的「重命名…」只改文件夹、不同步作业信息 ——
> 那会让文件夹名和作业信息对不上。现在两条路径都走同一套逻辑。

#### 作业信息文件（只读）

作业文件夹里的 `homework.json` 是软件的数据文件，列在列表里但**只读**：

* 类型列显示「作业信息」，显示为灰色；
* 右键只有「查看内容（只读）」「在资源管理器中显示」；
* **没有改名和删除入口** —— 动了它这条作业就会丢掉 DDL 与提交方式。

### 文件操作

**双击的行为**（都在软件内部完成，**不弹资源管理器**）：

| 双击的东西 | 结果 |

## 五、AI 学习总结

菜单：「工具 → 生成学习总结…」，或书目页的「生成总结」按钮。

### 生成流程

1. **收集资料**：`Introduct.md` + `notebook` 下全部文件 + `error-prone` 下全部文件。
   `book`（教材）、`homework`（作业/练习）与 `others`（其它文件）**都不参与**；
   其中 `book` 是代码级排除，改配置也不会生效。
2. **解析文本**：按类型选择读取器（见下表）。
3. **整合扩展**：把资料合并成一份完整学习文档——补推导、补条件、
   把易错题转成易错点清单、列出「待确认问题」。
4. **长资料处理**：超过「单次送入字符数」时自动切块 → 逐块提炼 → 合并成文。
5. **写盘**：先把上一版备份到 `else data/summary_backup`，再原子替换
   `<书名>_summary.md`。

### 生成前可先预览

「预览将总结的资料」会列出：哪些文件参与、哪些被跳过、每个文件的字符数、
识别可靠性说明，以及最终发送给 AI 的内容预览。还可以追加这次的重点要求
（例如「多补充例题」「按章节顺序整理」「面向期末考试」）。

### 各格式的处理方式

| 格式 | 处理方式 | 可靠性 |
| --- | --- | --- |
| `md` / `txt` | 直接读取（自动尝试 utf-8 / gbk / gb18030 等编码） | 高 |
| `pdf`（有文字层） | 按页提取文字 | 高 |
| `pdf`（扫描件） | 每页渲染为 PNG 插入 Markdown | 原图，不猜内容 |
| `docx` | 段落 + 标题层级 + 表格 → Markdown | 高 |
| `pptx` | 幻灯片文字 + 表格 + 备注 | 中（图表/图片未解析） |
| `xlsx` / `csv` | 工作表 → Markdown 表格（上限 300 行/表） | 中（公式取缓存值） |
| 图片 | 按 Markdown 图片语法插入 | 原图，不做 OCR |
| `.doc`/`.ppt`/`.xls` | 不支持，提示另存为新格式 | — |

> 原则：**准确性优先，其次是美观和便捷**（需求文档第五节）。
> 无法保证识别准确的内容一律不猜。

### 生成总结（合并成一个 PDF）

> 需求："AI总结实现方法：将所有待总结文件转化并合并为一个pdf文档，
> 结束后删除中间可能产生的废弃文档和数据"
> "不再生成md文档，旧的md之间删掉"

入口：书目页顶栏「**生成总结 PDF**」，或菜单「工具 → 生成总结…」。

**产物只有一个文件**：``<书目>_summary.pdf``（在书目目录下）。
生成结束后你**不会**在别处看到任何新增的东西 —— 页面图片、公式图片、
构建中的临时文件全部在结束时清掉（见下）。

**合并哪些**：`笔记` 与 `易错题` 两个目录里的全部文件（含子文件夹），
外加书目简介。软件自己的数据文件（`book.json` / `homework.json`）会跳过；
某个 PDF 的抽图目录（`xxx_pages/`）也会跳过 —— 否则同一份 PDF 会被插入两次。

**怎么合并**：每一份资料都转成**页面图片**再写进 PDF。

| 类型 | 处理方式 |
| --- | --- |
| PDF | **每页**渲染成一张图片（扫描件与文字版都一样） |
| 图片（png/jpg/…） | 原样放进页面 |
| Word / PPT / Excel / 文本 / Markdown | 先抽成 Markdown，再排版成图片页面 |

为什么连"能抽文字"的也走图片：需求要的就是"合并成一个 PDF"，
让阅读体验统一；而且**公式**本来就得渲染成图片
（Word 的公式是 OMML、总结里的公式是 LaTeX），一半文字一半图片拼出来更碎。
一条路径比两条路径少一半出错机会。

#### 「删除中间产生的数据」是怎么保证的

不是"生成完再去删干净"（那样一定会漏），而是**结构上**保证：

1. 所有页面图片与公式图片都放在一个**本次专用**的临时目录里
   （``%TEMP%\gwp_summary_*``），结束时无论成败整个删掉；
2. 全部内容先写进一个**临时 PDF**（``*.building.pdf``），
   中途失败就删掉它 —— **目标文件一个字节都不会动**；
3. 只有全部成功，才把临时 PDF 替换到目标位置。

所以"不留中间物"是**设计出来的**，而不是靠一份"记得删这些"的清单。

> 小提示：替换失败时会**自动重试**。如果你正用阅读器开着这个 PDF，
> 它可能会占住文件，导致替换不了 —— 这时关掉阅读器再点一次即可
> （原本的 PDF 不会被破坏）。

#### 「长庚知道」——文末的知识点补充

生成时会问一句"文末要不要加入「长庚知道」"，默认**勾上**。

勾上之后，AI 会在 PDF **最后面**追加几页补充，**每一页左上角**都印着
「长庚知道」四个字（底下带一条细线，看起来像个栏目标记而不是正文）。

这一块是总结里**唯一由 AI 写文字**的地方，所以边界是刻意划清的：

| 边界 | 具体做法 |
| --- | --- |
| 只写补充 | 提示词里明确要求：术语辨析、常见误区、知识联系、延伸 |
| 不复述资料 | 明确写了"不要重复资料里已经写过的内容" |
| 位置固定 | 接在**所有资料页之后**，不和资料混在一起 |
| 明确标注 | 首页有标题「长庚知道（AI 补充）」+ 一行说明"不属于你的原始资料" |
| 失败不致命 | AI 不可用/排版失败 -> **资料页照常生成**，只是少这一段补充 |

AI 看到的线索是每份资料的**开头一小段**（或文件名）——
目的是知道"这本书在讲什么"，不是读完全文。
线索是转页面时**顺手留下**的，不会为了写补充再把 PDF 读一遍。

#### 旧内容怎么处理

* **旧的 Markdown 总结会被删掉**（需求："旧的md之间删掉"）；
* 生成前的上一版会**自动备份**，可以从「版本管理」退回去；
* 确认框点「取消」就什么都不做。

#### AI 能做什么

点生成时会问要不要 **让 AI 按主题重排页序**：
它只读每份资料开头的线索来决定顺序，**不增、不删、不改内容**；
校验不过（漏页/多页/重复）就整条不用、退回原顺序。
不勾选就**完全不调用 AI**。

### （旧）文档合并（已废弃）

> 需求："summary中板块，不需要你补充内容了（或者你可以仅仅在文档末尾补充tips），
> 按照用户上传的文件来，不要AI识别文字了，直接插入图片或文件
> AIsummary中 AI可以根据自己的理解改变图片插入顺序，
> 实现不同文件夹内容，的混排插入"

入口：书目页顶栏「**生成总结**」，或菜单「工具 → 生成总结…」。
（原来的「合并资料到总结」已并入它 —— 两件事本来就是一件。）

**AI 不再写正文。** 点下去得到的是"标题 + 资料图片"，
内容**原样来自你的文件**，未经 AI 改写。

**插入哪些**：`笔记` 与 `易错题` 两个目录里的**全部文件**（含子文件夹），
外加书目简介。软件自己的数据文件（`book.json` / `homework.json`）会跳过；
某个 PDF 的抽图目录（`xxx_pages/`）也会跳过 —— 否则同一份 PDF 会被插入两次。

**怎么插入 —— 按文件类型分流**：

| 类型 | 插入方式 | 说明 |
| --- | --- | --- |
| **图片型 PDF**（扫描件） | **图片** | **每页**转成一张图片 |
| **文字型 PDF** | 文字 | 文字直接插入，**公式渲染成图片** |
| **doc / docx** | 文字 | 同上；Word 公式（OMML）会转成 LaTeX 再渲染成图片 |
| **md / markdown** | **直接融合** | 当作文字插入（相对图片路径会改写成绝对路径） |
| **xls / xlsx**（表格） | 图片 | 版面即内容，转文字会把表格压扁 |
| **ppt / pptx**（幻灯） | 图片 | 同上 |
| **图片**（png/jpg/…） | 图片 | 原样复制 |
| 其它类型 | **会先问你** | 不擅自决定；先在文末列出，等你确认 |

**怎么判断"文字型 / 图片型"PDF**：按文字层是否可用 + 每页平均字符数
（由 `document_reader` 判断）。判不出来时**按图片型处理** ——
宁可插入完整页面图片（内容一定不丢），也不要插进一堆乱码文字。

> Word 的公式是一套 XML（OMML），不是文字也不是 LaTeX。
> 软件会把它转成 LaTeX 再渲染成图片；**转不出来就退回纯文字**，绝不硬凑。

**图片之间的间隙**：连续的多张图片会被合成一组，
**图与图之间没有间隙**；最后一张图与下面的文字之间只留一点点呼吸空间
（完全贴死会挤在一起，反而更难读）。

**图片存哪**：

```
<数据目录>/else data/merged/<书目>/       原始资料转出来的图
<数据目录>/else data/equations/           LaTeX 公式渲染出来的图
```

放在 `else data`（软件数据侧）**不放在书目里** —— 它们是生成物，
不该混进你的资料目录，集中存放也便于清理。

#### AI 混排页序（可选，默认关闭）

点「生成总结」时会问你要不要 **让 AI 按主题重排页序**。勾上之后：

* AI 会读**每页开头一小段文字**（约 160 字），判断这一页讲什么；
* 然后给出一个页序，把同一知识点的页排在一起 ——
  于是**不同文件夹的内容会真正交错穿插**，而不是一个文件接一个文件；
* **它只决定顺序，不增、不删、不改任何一页的内容**；
* 校验很严：只要 AI 漏页、多页或重复，就**整条拒绝**、退回原顺序 ——
  排错一份会丢页，那比不混排严重得多；
* AI 不可用、回复不是 JSON、页数超过 600 —— 任何一种失败都只是
  **退回原顺序**，不会让生成失败。

不勾选就**严格按文件顺序插入，完全不调用 AI**（不发一个请求）。

#### 使用提示（文档末尾）

summary 末尾有一段固定的「使用提示」小节 —— 这是需求里说的
"可以在文档末尾补充 tips"。它是**固定文字**，不是每次让 AI 现编：
固定文字才能保证同一句话在任何一次生成里都一致、可预期。

#### 几件刻意做的事

* **旧内容先自动备份**：summary 会被**整个重写**，旧版存在
  「版本管理」里，随时能退回去；
* **重复执行不会越插越多**：是重写，不是追加；
* **单份资料失败不影响其它**：失败的那份在末尾列出原因，原文件不动；
* **确认框点取消 = 什么都不做**（summary 一个字节都不动）。

### 公式渲染成图片

LaTeX 公式在软件里**渲染成图片**再显示 —— 因为预览用的 `QTextBrowser`
只支持 HTML4 + CSS2.1 的一个子集，**不认识 LaTeX**；
不处理的话你会看到 `$\varepsilon > 0$` 这样的源码。

排版能力（自己用 Pillow 排的，**不额外引入 matplotlib**）：

| 能排 | 说明 |
| --- | --- |
| 上下标、分式、根号 | `x^2`、`\frac{1}{n}`、`\sqrt{x}` |
| 上下限堆叠 | `\lim_{n\to\infty}`、`\sum_{i=1}^{n}`、`\int_0^1` |
| 希腊字母与常用符号 | α β ε δ Σ ∫ ∑ ∞ ≤ ≥ ∈ ∀ ∃ → … |
| 函数名保持正体 | sin cos log ln lim max min |

排不出的（矩阵、多行对齐等）**不猜**：整条按纯文本显示并标注退化，
宁可显示得朴素，也不画出错误的东西。

> 公式图片按内容哈希命名，同一条公式只存一份、可复用。

### 后台自动刷新（文件变化监听）

> 需求："软件后台要不断扫描 user data 文件夹，更新文件变动，
> 但不要耗费 cpu 太多性能"

软件会**一直盯着 `data\user data\subjects`**：你在资源管理器里新建/删除/改名
科目、书目、笔记，或者用别的程序改了文件，**最多约 6 秒**界面就自动刷新，
不用重启。

**实测代价（本机数据 + 5000 项假数据都测过）**：

| 场景 | 单核占用 |
| --- | --- |
| 窗口开着、空闲 | **0.55% 单核**（实测，32 核机器上是整机 0.017%）|
| 窗口隐藏到后台 / 最小化 | **0%（完全停掉）** |

怎么做到这么低的 —— 三条，每条都有实测依据：

1. **用 `os.scandir` 而不是 `rglob`**。
   5000 项时前者 10 ms、后者 243 ms，**差 23 倍**（这是能把间隔取到 2 秒的原因）。
   原因是 Windows 的目录项里已经带了文件信息，`scandir` 不用再问一遍文件系统。
2. **只在真变化时才重建界面**。
   每次扫描只做最便宜的事：拿一份「路径 → 修改时间」快照，和上一份比。
   只有真的不同，才去让缓存失效并重画 —— 那一步要 26 ms，绝不能每 5 秒做一次。
3. **看不见就不扫**。窗口隐藏或最小化时定时器**完全停掉**；
   恢复显示时立刻补扫一次，所以"后台改了文件、切回来"也能马上看到。

> 为什么"稳定下来才认账"不会让你等太久：观察窗口是**固定 4 秒**
> （不是"固定次数"）。所以间隔能取到 2 秒而依然稳妥 ——
> 改动最多约 6 秒可见，而不是"两次一致"那种要 10 秒以上。

**怎么调**：`else data\config.json` 里

```json
"ui": {
  "data_scan_interval_ms": 2000,     // 单位毫秒；调大更省（如 15000，最小 1000）
  "auto_refresh_on_change": true     // 设 false 就完全关掉自动刷新
}
```

**为什么不会"闪一下又变回来"**：要求**连续两次看到同一个新状态**才认账。
本软件自己保存笔记、生成总结也会改文件时间 —— 一发现不同就刷新的话，
可能正好抓到"写到一半"的中间状态。多看一眼就把这种中间态过滤掉了。

### 生成结果提示

完成后会告知：参与资料数与总字符数、实际使用的 AI、耗时、
上一版备份位置、被跳过的空文件数。生成过程中可随时取消。

## 六、Summary 版本管理

需求文档第六节：保存上一版本、新旧替换、只保留一个上一版。

* 位置：`data\else data\summary_backup\<科目>\<书目>\<时间戳>\`
* 生成新总结时，把当前 `summary` 复制过去；`backup_keep` 默认 1，超出自动清理。
* **标题栏空间有限，按钮文案按最省写**，完整含义都在悬浮提示里：

  | 按钮 | 说明 |
  | --- | --- |

## 十、导出 PDF

need.md 第 5 条：把 md 导出为 pdf，可自定义导出位置。

* 入口：「文件 → 导出当前文档为 PDF…」、`Ctrl+P`、书目页「导出 PDF…」、
  文档视图的「导出 PDF」按钮、右侧「资料概览 → 把总结导出为 PDF」。
* **导出对象的选择规则**（书目页的「导出 PDF…」）：

  1. 当前标签页里**选中的文件**优先；选中的是文件夹时，取其中第一个可导出文件；
  2. 没有选中任何文件时，回退到本书的 `<书名>_summary.md`；
  3. 两者都没有则提示先选文件或先生成总结。

  对话框顶部会明确显示「将导出：<文件名>」，避免导错对象。
* 自定义项：保存位置、纸张（A4/A5/B5/Letter/Legal）、页边距、
  是否把图片嵌入 PDF（嵌入后 PDF 可独立于原文件）。
* **导出前会弹窗确认两件事**（Markdown 排版之前没有"页"的概念，所以先排版再问）：

  1. **是否添加页码** —— 默认添加，页脚居中显示 `- 页码 / 总页数 -`；
     页码用的是**原文档中的页号**：从 10 页里只导第 8 页时，页脚仍是「8 / 10」。
  2. **导出哪些页** —— 默认「全部」，也可以自己写范围：

     | 写法 | 含义 |
     | --- | --- |
     | `1-3, 5, 8-10` | 第 1~3 页、第 5 页、第 8~10 页 |
     | `e` | 最后一页（e = end） |
     | `e-1` | 倒数第二页 |
     | `e-2-e` | 倒数第三页到最后一页 |
     | `3-e` | 第 3 页到最后一页 |
     | 留空 | 全部页 |

     输入会**即时校验**并在对话框里显示结果（例如「将导出 共 4 页：1, 2, 3, 5」）；
     不合法时确定按钮直接禁用并给出原因，例如 `2-1` 会提示
     「区间反了：起始页 2 大于结束页 1」，`11`（超出总页数）会提示实际页数。
     多段之间可用中英文逗号、顿号、分号或空格分隔；`1 - 3` 与 `1-3` 等价。
     不想每次都弹窗，可取消勾选「导出前询问页码范围」。
* 左侧提供效果预览；导出后可勾选「记住这次的选择」。
* **后台执行**：排版、切页、编号、写盘全部在后台线程完成，带进度显示，可随时取消；
  取消或失败会清掉半成品与临时文件，不会留下损坏的 PDF。
* **完全本地生成**（PyMuPDF），不需要联网、不需要 Office、不需要浏览器。

## 十一、主界面背景

主界面（科目总览 / 科目页 / 书目页）支持设置背景图片。

* **图片存放位置**：`data\else data\background`（该目录就是背景图库）。
  可以直接把图片丢进去，也可以在软件里导入。
* **入口**：菜单「**查看 → 更改背景**」（或在「设置 → 更改背景」，两处入口内容完全一致），
  里面有

  | 菜单项 | 作用 |
  | --- | --- |
  | 当前：<文件名> | 只读显示当前用的是哪张 |
  | 选择背景图… | 打开背景对话框：导入、预览、切换、调效果（`Ctrl+Shift+B`） |
  | 图库列表 | 直接点某张图切换（当前那张前面有 ✔） |
  | 启用背景图 | 临时关掉背景，但**保留**设置，随时勾回来 |
  | 不使用背景（图片保留） | 停止使用背景，**图片文件不删除** |
  | 打开背景文件夹 | 在资源管理器中打开图库目录 |

* **更换背景不会删除旧图**：新图片会被复制进图库，文件名只递增后半部分的数字：

  | 操作 | 结果 |
  | --- | --- |
  | 第一次导入 `桌面.png` | `桌面.png` |
  | 再导入同一张 | `桌面_1.png` |
  | 第三次导入 | `桌面_2.png` |
  | 导入素材 `桌面_9.png` | `桌面_3.png`（以主名递增，不会变成 `桌面_9_1.png`） |

  因此可以随时在菜单里切回任意一张历史背景。
* **可调效果**：
  * **显示方式**：铺满（裁掉多余）/ 完整显示 / 拉伸 / 原尺寸居中；
  * **蒙层深浅**：默认 **0（不压暗）**，背景原样显示；
    如果你觉得背景太抢眼、想让它退到后面，往右拉即可（0~90%）。
* **背景铺满整个工作区，内容块浮在上面**：

  * 背景画在整个工作区上，中间的页面区域是透明的，所以背景**从内容块之间的
    空隙里透出来**，包括科目列表那片区域；
  * 科目卡片、资料概览面板、表格、按钮各有自己的不透明底色，文字始终看得清；
  * 页面顶部的标题栏（「我的科目 / 搜索框 / 新建科目」这一行）有一层
    **半透明织带** —— 它是唯一"文字直接压在图上"的地方，加这一层是为了让
    深色壁纸上也能看清；
  * 背景**不用 CSS 画**，而是主界面控件自己用 `QPainter` 绘制
    （见 `ui/widgets/background_area.py`），因此不会与主题样式表冲突，
    拖动窗口也会缓存缩放结果，不会卡。
* 背景只挂在主界面容器上，弹出的设置窗口、文档窗口不受影响。
* `ui.background_margin` 设为大于 0 时，背景会变成"外框"样式（内容区四周留边）；
* 当前使用哪一张记录在 `config.json` 的 `ui.background_image`（相对路径），
  因此整个 `data` 目录搬到别的磁盘也不会丢背景。

## 十三、启动优化与系统集成

需求文档第十三节：支持开机自动启动、提前完成文件扫描。

### 单实例（同一时间只有一个主窗口）

软件在 `else data\instance.lock` 里记录正在运行的**进程号与主窗口句柄**，
**同一个数据目录只允许一个主窗口**：

* 重复双击快捷方式时，第二个进程会弹一个提示「Great White Planet 已经在运行了」
  然后自动退出（退出码 2），不会出现两个主界面各自维护扫描结果；
* 如果上一个实例是崩溃/被强杀退出的，锁文件里的进程号已经不存在，
  新启动会自动接管（不会卡住打不开）；
* 锁文件损坏、为空、内容不是数字时同样视为可启动；
* 开发或对比时需要多开，可以加参数 `--allow-multiple`（会跳过检查）；
* 自动化/脚本启动时若不想弹提示框，可设置环境变量 `GWP_NO_PROMPT=1`。

### Win11 多桌面（虚拟桌面）

Windows 11 的"多桌面"其实是同一个桌面命名空间，如果不做处理会有两个问题：
窗口默认**在每个桌面都出现**；在第二个桌面启动时又看不到任何反应。

现在的行为：

| 情况 | 结果 |
| --- | --- |
| 在桌面 1 打开软件，切换到桌面 2 | 软件只在**它自己的桌面**上显示，不会跟着跑到桌面 2 |
| 在桌面 2 再双击启动 | **弹窗提示**「软件已在另一个桌面上运行」，并说明怎么切过去，本次启动退出（退出码 2） |
| 提示框里的「切到那个桌面」 | 尝试自动把桌面切过去并激活已有窗口（Windows 对程序主动切换桌面有限制，失败时会提示手动按键） |

* 提示框里会写明三种切过去的办法：`Win + Ctrl + ←/→`、`Win + Tab` 任务视图、
  或者直接点「切到那个桌面」按钮。
* 切换桌面靠系统接口 `IVirtualDesktopManager::IsWindowOnCurrentVirtualDesktop`
  判断已有窗口在哪，**不依赖任何第三方库或系统版本魔法**。
* 接口不可用、判断失败时**一律按"同桌面"处理** —— 宁可少拦一次，
  也不要误拦导致软件打不开。
* 日志里会打印判定结果（`桌面判定=True/False/None`），排错时一眼能看到。

### 开机自动启动

* 设置 → 启动与集成，或「文件 → 开机自动启动」。
  写入注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，
  使用 `pythonw.exe` 静默启动（不弹控制台）。
* **启动预扫描**：启动后立即在后台线程扫描科目/书目结构并写入缓存，
  首页会提示「预扫描完成，共 N 个科目」，减少正式使用时的等待。
* **桌面快捷方式**：一键创建/删除（设置 → 启动与集成，或「文件」菜单）。
  快捷方式图标使用 `resources/icons/planet.ico`（内置绘制的「太白金星」，
  可在设置里换成自己的图片）。
* **扫描缓存**：`else data/cache/scan_cache.json`，记录每个科目目录的修改时间；
  可在「工具 → 重建扫描缓存」里清理。

## 十四、数据与安全

需求文档第十节：用户数据在 `data`，非用户上传内容在 `else data`，
图片等资源不直接存入用户数据。

```
data
├── user data                        用户自己的内容
│   └── subjects/<科目>/<书目>/...   科目与书目
└── else data                        软件产生的数据
    ├── config.json                  配置（可直接编辑）
    ├── secrets.json                 API Key
    ├── background/                  主界面背景图库
    ├── summary_backup/              总结的上一版
    ├── assets/subjects/<科目>/      科目卡片图片
    ├── chats/                       AI 聊天记录
    ├── cache/scan_cache.json        扫描缓存
    └── logs/                        运行日志
```

* **原子写**：Markdown、配置、总结都是「先写临时文件再替换」，避免写一半损坏。
* **删除默认进回收站**（Windows `SHFileOperation`，不依赖 pywin32）。
* **删除要过两道确认，且回车等于取消**：
  删除科目/书目时弹的是**警告框**，「删除」按钮必须主动点击，
  **默认按钮是「取消」** —— 手快按到回车不会把数据删掉；
  内容非空时还会再问一次。
  文案会**如实**说明后果：能进回收站才写「可从回收站还原」，
  回收站不可用时明确写「永久丢失、无法还原」。
* **覆盖前先备份**：重新生成总结会保留上一版；恢复上一版时又会先备份当前版本。
* **日志**：按天切分，默认保留 14 天。启动失败会另写
  `logs/startup_error.log`，里面含完整堆栈。
* 导出 PDF 的中间文件（`.layout` / `.pages` / `.extract` / `.part`）在完成后立即清理，
  取消或失败时也会清掉，不会在资料目录里留下垃圾。

## 十七、扩展点（给后续升级用）

| 想做什么 | 怎么做 |
| --- | --- |
| 支持新文件格式 | `services/document_reader.py` 里 `register_reader({".epub"}, reader)` |
| 接入新 AI | `ai/providers/` 新建文件，继承 `BaseAIAdapter` + `@register_provider`，再在 `config.json` 加一段配置 |
| 调整总结风格 | 设置 → 提示词，或改 `config.json` 的 `prompts` 段 |
| 改外观 | 设置 → 界面（主题/主色/字体/卡片尺寸），或改 `services/themes.py` |
| 换主界面背景 | 设置 → 主界面背景（图片放在 `else data/background`） |
| 换程序图标 | 设置 → 启动与集成 → 更换程序图标，或 `gwp.cli icon --image` |
| 迁移数据位置 | 设置 → 存储路径，改数据根目录后重启 |
| 加界面动作 | 在对应 View 里加按钮，业务逻辑走 `Library` / `Summarizer` |
| 加新页面分类 | `ui/views/book_view.py` 的 `TABS` 里加一项 |

软件为这些扩展预留了注册表与配置文件，**新增功能不需要修改已有模块**。
