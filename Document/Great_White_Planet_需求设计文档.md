# Great White Planet 软件需求设计文档

## 一、软件定位

Great White Planet 是一个本地知识管理与 AI 辅助学习软件。

核心目标：

-   管理课程、教材、笔记、错题
-   使用 AI 整合学习资料
-   自动生成结构化总结文档
-   支持后续持续升级和扩展

------------------------------------------------------------------------

# 二、整体层级结构

软件采用：

    Subject
     └── Book
          ├── Introduct.md
          ├── Book_summary.md
          ├── book
          ├── error-prone
          └── notebook
#其中Subject Book
------------------------------------------------------------------------

# 三、Subject设计

## 首页

首页采用图形化显示。

默认：

-   彩色长方体卡片

例如：

    ┌──────┐
    │ 高代 │
    └──────┘

------------------------------------------------------------------------

## Subject功能

支持：

-   新建 Subject
-   删除 Subject
-   修改 Subject 名称
-   更换 Subject 图片

图片支持：

-   jpg
-   png

用户右键 Subject 卡片进行操作。

------------------------------------------------------------------------

## Subject存储

每个 Subject 对应一个文件夹：

    data
    └── subjects
        └── 高代

软件自动扫描文件夹生成界面。

不使用代码写死课程名称。

------------------------------------------------------------------------

# 四、Book设计

点击 Subject 后进入 Book 页面。

每个 Book 自动创建：

    Book名称

    ├── Introduct.md
    ├── Book名称_summary.md
    ├── book
    ├── error-prone
    └── notebook

------------------------------------------------------------------------

## 文件夹用途

### Introduct.md

-   用户自行编辑
-   用于记录 Book 简介、学习目标等信息

------------------------------------------------------------------------

### book

存放：

-   电子教材
-   PDF教材

注意：

book 文件夹内容不参与 AI 总结。

------------------------------------------------------------------------

### error-prone

存放：

-   错题
-   易错内容

参与 AI 总结。

------------------------------------------------------------------------

### notebook

存放：

-   用户笔记

参与 AI 总结。

------------------------------------------------------------------------

# 五、Summary生成规则

AI生成文件：

    Book名_summary.md

默认位于 Book 首位。

------------------------------------------------------------------------

## Summary原则

不是简单概括。

要求：

-   整合所有相关文件
-   扩展内容
-   形成完整学习文档

本质：

将多个文件整合为一个更完善的 Markdown 文件。

------------------------------------------------------------------------

## Summary包含内容

AI总结：

-   Introduct.md
-   notebook 文件夹内容
-   error-prone 文件夹内容

book 文件夹：

不参与总结。

------------------------------------------------------------------------

## PDF处理

notebook 中的 PDF：

如果：

-   文字识别准确

则：

转换为文字。

如果：

-   无法保证识别准确

则：

直接以图片形式插入 Markdown。

原则：

准确性优先，其次是美观和便捷。

------------------------------------------------------------------------

# 六、Summary版本管理

采用方案：

保存上一版本。

位置：

    data
    └── summary_backup

规则：

-   summary更新时保存上一版
-   新旧替换
-   只保留一个上一版本

目的：

兼顾安全性和存储空间。

------------------------------------------------------------------------

# 七、AI系统设计

AI采用可插拔结构。

支持：

## DeepSeek

-   DeepSeek API
-   DeepSeek网页版

## GPT

-   GPT API
-   GPT网页版

------------------------------------------------------------------------

## AI选择

顶部菜单：

    AI

    ├── 当前AI
    ├── DeepSeek API
    ├── DeepSeek网页版
    ├── GPT API
    ├── GPT网页版
    ├── 刷新AI
    ├── 重新发送文件
    ├── 删除聊天记录
    └── AI设置

------------------------------------------------------------------------

## AI规则

首次在文件中打开 AI：

自动发送当前文件。

关闭 AI：

保存聊天记录。

关闭软件：

清除所有 AI 聊天记录。

------------------------------------------------------------------------

## AI交互

如果 AI 对内容存在不确定：

可以：

-   弹窗询问用户
-   接收用户回答
-   根据回答继续处理

------------------------------------------------------------------------
